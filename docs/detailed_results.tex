\begin{center}
{\Large\bfseries Detailed Results on the New Instances}\\[0.8em]
Supplement to W.~Wang, ``Enhanced Exact Solution of the Electric Vehicle Routing\\
and Overnight Charging Scheduling Problem''
\end{center}

\vspace{1em}
Tables~\ref{tab:n60}--\ref{tab:n100} report the results of our branch-price-and-cut algorithm on each of the 280 new instances with 60, 70, 80, 90, and 100 customers. They are the runs of Section~6.4 of the paper: Java~17 and Gurobi~12.0.0 on one core of an AMD EPYC~9655 processor of the Fir cluster, with 32~GB of memory and a time limit of 7{,}200 seconds that includes the initial heuristic. The logs of these runs are in the folder \texttt{results/new/ours} of the repository, and this document is generated from them.

The columns are the following.
\begin{itemize}
\setlength{\itemsep}{0.2em}
\item $B$: number of chargers.
\item Init.\ UB: value of the solution of the initial heuristic; a dash indicates that the heuristic found no feasible solution within its time limit.
\item UB: value of the best solution found.
\item LB: global lower bound at the end of the run; a dash indicates that the root node was not completed.
\item Gap (\%): $100(\mathrm{UB}-\mathrm{LB})/\mathrm{UB}$.
\item Time (s), Total: computing time, including the initial heuristic; TL indicates that the time limit was reached.
\item Time (s), Best: time at which the best solution was found.
\item Nodes: number of processed branch-and-bound nodes.
\item Closed by, Enum.: number of nodes solved by the charging-flexible models over the paths enumerated with the whole gap (Section~5.2).
\item Closed by, Cert.: number of nodes closed by the certificate of the enumeration ladder (Proposition~7).
\item Veh.: number of vehicles in the best solution.
\end{itemize}
